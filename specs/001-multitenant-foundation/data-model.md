# Data Model: Nền tảng SaaS đa tenant

## Conventions

- IDs are UUIDs generated by the server/database. Public identifiers are never authorization evidence.
- Timestamps are UTC `timestamptz`; tenant timezone is used only when deriving business dates.
- Every mutable table has `created_at`, `updated_at`; historically significant changes also
  produce append-only audit/history records.
- Every tenant-owned table below has mandatory `tenant_id` and an index beginning with it.
- Composite parent keys include `(tenant_id, id)` so child rows cannot reference another tenant.
- Secrets (refresh/invite tokens) are stored only as hashes. JSON audit fields are redacted.
- `version` integer columns provide optimistic concurrency where concurrent edits are valid.

## Global and Root Entities

### User

Global account; not tenant-owned.

| Field | Type | Rules |
|---|---|---|
| id | UUID | PK |
| full_name | string | required after onboarding, 2–120 chars |
| full_name_confirmed_at | timestamp? | required before tenant creation/join |
| status | enum | `ACTIVE`, `SUSPENDED`, `DELETED` |
| locale | string | default `vi-VN` |
| created_at / updated_at | timestamp | server values |

Unique identity is not based on email or name.

### ExternalIdentity

| Field | Type | Rules |
|---|---|---|
| id | UUID | PK |
| user_id | UUID | FK User |
| provider | enum | MVP `GOOGLE` |
| provider_subject | string | stable provider `sub` |
| email | string? | informational, normalized |
| email_verified | boolean | provider claim |
| last_login_at | timestamp | server time |

Unique `(provider, provider_subject)`. Email is not unique authority.

### AuthSession

| Field | Type | Rules |
|---|---|---|
| id | UUID | PK / JWT session id |
| user_id | UUID | FK User |
| refresh_token_hash | bytes/string | unique, never return after issuance |
| token_family_id | UUID | rotation/reuse group |
| expires_at | timestamp | required |
| revoked_at | timestamp? | null when active |
| revoke_reason | string? | sanitized |
| replaced_by_session_id | UUID? | refresh rotation chain |
| device_label / user_agent_hash / ip_prefix | string? | privacy-minimized security metadata |
| created_at / last_used_at | timestamp | server time |

Indexes: `(user_id, revoked_at, expires_at)`, `(token_family_id)`.

### NotificationEndpoint

Global per-user device registration; notifications referencing business data remain tenant-scoped.

| Field | Type | Rules |
|---|---|---|
| id | UUID | PK |
| user_id | UUID | FK User |
| platform | enum | `IOS`, `ANDROID` |
| provider | enum | `FCM`, `APNS` |
| token_ciphertext | bytes/string | encrypted at rest in production |
| token_fingerprint | string | unique dedup key |
| status | enum | `ACTIVE`, `INVALID`, `REVOKED` |
| last_seen_at / revoked_at | timestamp? | lifecycle |

Unique `(user_id, token_fingerprint)`; an endpoint is modifiable only by the same user.

### Permission

Global immutable catalog (`tenant.read`, `branch.manage`, `member.manage`, `role.manage`,
`form.manage`, `form.submit`, `chat.read`, `chat.write`, `media.create`, `media.read`,
`audit.read`).

| Field | Type | Rules |
|---|---|---|
| id | UUID | PK |
| code | string | globally unique, immutable |
| description | string | required |
| allowed_scopes | enum[]/JSON | tenant and/or branch |

### SecurityEvent

Append-only global account/security audit used when no tenant exists yet.

Fields: `id`, `user_id?`, `session_id?`, `event_type`, `correlation_id`, `ip_prefix?`,
`user_agent_hash?`, `metadata_redacted`, `occurred_at`. No update/delete API.

### AccountIdempotencyRecord

Global/account-scope deduplication for login profile completion and tenant creation.

Fields: `id`, `user_id`, `operation`, `key`, `request_hash`, `status` (`PROCESSING`,
`COMPLETED`, `FAILED_RETRYABLE`), `response_status?`, `response_body_redacted?`, `resource_id?`,
`locked_until`, `expires_at`, timestamps. Unique `(user_id, operation, key)`.

### Tenant

Root of a tenant data graph; the tenant row itself is not a child of another tenant.

| Field | Type | Rules |
|---|---|---|
| id | UUID | PK |
| name | string | 2–160 chars |
| slug | string | globally unique public selector, not authorization evidence |
| timezone | string | valid IANA zone, default `Asia/Ho_Chi_Minh` |
| status | enum | `ACTIVE`, `SUSPENDED`, `CLOSED` |
| settings | JSON | non-authoritative presentation/default settings only |
| created_by_user_id | UUID | FK User |
| created_at / updated_at | timestamp | server values |

## Tenant-Owned Organization and RBAC

### Branch

Fields: `tenant_id`, `id`, `code`, `name`, `timezone_override?`, `status`, timestamps,
`created_by_membership_id`. Unique `(tenant_id, code)` and `(tenant_id, id)`.

### Department

Fields: `tenant_id`, `id`, `code`, `name`, `status`, timestamps. Unique `(tenant_id, code)`.

### Position

Fields: `tenant_id`, `id`, `code`, `name`, `status`, timestamps. Unique `(tenant_id, code)`.

### TenantMembership

| Field | Type | Rules |
|---|---|---|
| tenant_id / id | UUID | composite tenant identity |
| user_id | UUID | FK User |
| membership_display_name | string | 2–120 chars |
| employee_code | string? | unique inside tenant when set |
| status | enum | `INVITED`, `ACTIVE`, `SUSPENDED`, `LEFT` |
| joined_at / suspended_at / left_at | timestamp? | lifecycle |
| version | integer | optimistic concurrency |

Unique `(tenant_id, user_id)`, `(tenant_id, employee_code)` when employee code is present.
Name changes are audited; references use membership ID.

### Assignment

Represents effective work assignment, not authorization.

Fields: `tenant_id`, `id`, `membership_id`, `branch_id`, `department_id?`, `position_id?`,
`effective_from`, `effective_to?`, `status`, `created_by_membership_id`, `reason?`, timestamps.

Rules:

- All referenced organization records share the same tenant through composite FKs.
- `effective_to > effective_from` when present.
- Multiple department/position assignments may overlap intentionally.
- Exact duplicate effective assignments are rejected; edits create a new historical row or audited transition.

Indexes: `(tenant_id, membership_id, effective_from, effective_to)`,
`(tenant_id, branch_id, effective_from, effective_to)`.

### Role

Fields: `tenant_id`, `id`, `code`, `name`, `kind` (`SYSTEM`, `CUSTOM`), `status`, timestamps.
System roles `TENANT_OWNER`, `MANAGER`, `EMPLOYEE` are seeded per tenant. Unique
`(tenant_id, code)`; system roles cannot be deleted/renamed incompatibly.

### RolePermission

Fields: `tenant_id`, `role_id`, `permission_id`, timestamps. PK/unique
`(tenant_id, role_id, permission_id)`. Permission is global; role composite FK enforces tenant.

### MembershipRoleBinding

| Field | Type | Rules |
|---|---|---|
| tenant_id / id | UUID | tenant-owned identity |
| membership_id / role_id | UUID | same-tenant composite FKs |
| scope_type | enum | `TENANT`, `BRANCH` |
| branch_id | UUID? | required only for `BRANCH`, same tenant |
| effective_from / effective_to | timestamp | effective permission interval |
| granted_by_membership_id | UUID | authorized actor |
| reason | string? | required for privileged corrections |

Unique logical binding across membership/role/scope/effective start. Last active Tenant Owner
cannot be suspended, removed, expired, or have its owner binding revoked.

### Invitation

| Field | Type | Rules |
|---|---|---|
| tenant_id / id | UUID | tenant-owned identity |
| token_hash / token_hint | string | hash unique globally; hint safe to display |
| invitation_type | enum | `DIRECT`, `GROUP_LINK` |
| role_id | UUID | same-tenant role |
| branch_id | UUID? | optional initial scope |
| max_uses / use_count | integer | default 1; non-negative |
| expires_at / revoked_at | timestamp | lifecycle |
| created_by_membership_id | UUID | actor |

State derives as `ACTIVE`, `EXPIRED`, `REVOKED`, `EXHAUSTED`. Plain token is shown only once.

### InvitationAcceptance

Fields: `tenant_id`, `id`, `invitation_id`, `user_id`, `membership_id`, `accepted_at`,
`correlation_id`. Unique `(tenant_id, invitation_id, user_id)` and
`(tenant_id, membership_id)`. Created in the same transaction as use-count increment.

## Tenant-Owned Dynamic Forms

### FormTemplate

Fields: `tenant_id`, `id`, `code`, `name`, `description?`, `status` (`ACTIVE`, `ARCHIVED`),
`current_published_version_id?`, `created_by_membership_id`, timestamps. Unique `(tenant_id, code)`.

### FormVersion

Fields: `tenant_id`, `id`, `form_template_id`, `version_number`, `status` (`DRAFT`,
`PUBLISHED`, `RETIRED`), `json_schema` JSONB, `ui_schema` JSONB?, `effective_from?`,
`published_at?`, `published_by_membership_id?`, timestamps.

Unique `(tenant_id, form_template_id, version_number)`. Published schema/UI are immutable;
a subsequent edit creates the next version. Schema must declare draft 2020-12 and reject
unknown field definitions outside the supported MVP vocabulary.

### FormSubmission

Fields: `tenant_id`, `id`, `form_template_id`, `form_version_id`, `submitted_by_membership_id`,
`branch_id?`, `data` JSONB, `status` (`SUBMITTED`, `VOIDED`), `submitted_at`, `voided_at?`,
`void_reason?`, `idempotency_key`, timestamps.

Unique `(tenant_id, submitted_by_membership_id, idempotency_key)`. Composite FKs guarantee
template/version/submitter/branch share a tenant. Data cannot be updated after submit; corrections
create a new submission linked through an optional `supersedes_submission_id`.

## Tenant-Owned Chat

### ChatChannel

Fields: `tenant_id`, `id`, `type` (`TENANT_GENERAL`, `BRANCH`, `GROUP`), `name`, `branch_id?`,
`status`, `created_by_membership_id`, timestamps. Room key is derived server-side as
`tenant:{tenant_id}:channel:{id}`. Unique channel constraints are tenant-scoped.

### ChatChannelMembership

Fields: `tenant_id`, `channel_id`, `membership_id`, `role` (`MEMBER`, `MODERATOR`),
`joined_at`, `left_at?`, `last_read_message_id?`. Unique `(tenant_id, channel_id, membership_id)`.

Tenant general channel MAY infer all active memberships; branch/group channels require explicit
or rule-generated membership rows that are still authorization checked.

### ChatMessage

Fields: `tenant_id`, `id`, `channel_id`, `author_membership_id`, `author_display_name_snapshot`,
`client_message_id`, `body`, `message_type`, `reply_to_message_id?`, `created_at`, `edited_at?`,
`deleted_at?`. Unique `(tenant_id, author_membership_id, client_message_id)`. Soft delete/edits
are audit transitions; original history is not physically overwritten without an audit snapshot.

Indexes: `(tenant_id, channel_id, created_at, id)` for cursor pagination.

## Tenant-Owned Media and Governance

### MediaObject

| Field | Type | Rules |
|---|---|---|
| tenant_id / id | UUID | tenant-owned identity |
| owner_membership_id | UUID | same-tenant actor/owner |
| branch_id | UUID? | same-tenant scope |
| source_type / source_id | string / UUID? | authorized business source |
| purpose | enum | extensible allow-list |
| storage_provider / bucket / object_key | string | key begins with tenant scope |
| content_type / byte_size / checksum_sha256 | scalar | server-validated limits |
| status | enum | `PENDING_UPLOAD`, `READY`, `REJECTED`, `DELETED` |
| upload_expires_at / ready_at / deleted_at | timestamp? | lifecycle |
| retention_until / legal_hold_at | timestamp? | deletion controls |

Unique `(storage_provider, bucket, object_key)` and `(tenant_id, id)`. Completion from READY is
idempotent; status cannot return to PENDING. Binary is never stored in PostgreSQL.

### AuditEvent

Tenant-scoped append-only event.

Fields: `tenant_id`, `id`, `actor_membership_id?`, `actor_user_id?`, `correlation_id`,
`event_type`, `target_type`, `target_id?`, `reason?`, `before_redacted` JSONB?,
`after_redacted` JSONB?, `metadata_redacted` JSONB?, `occurred_at`.

Indexes: `(tenant_id, occurred_at, id)`, `(tenant_id, target_type, target_id, occurred_at)`,
`(tenant_id, actor_membership_id, occurred_at)`. No update/delete repository method.

### TenantIdempotencyRecord

Fields mirror AccountIdempotencyRecord plus mandatory `tenant_id` and `membership_id`.
Unique `(tenant_id, membership_id, operation, key)`. A reused key with different request hash
returns conflict; completed safe responses may be replayed until expiry.

## State Transitions

```text
TenantMembership: INVITED -> ACTIVE -> SUSPENDED -> ACTIVE
                                  \-> LEFT (terminal for that membership)

Invitation: ACTIVE -> EXPIRED | REVOKED | EXHAUSTED

FormVersion: DRAFT -> PUBLISHED -> RETIRED

MediaObject: PENDING_UPLOAD -> READY -> DELETED
                              \-> REJECTED

AuthSession: ACTIVE -> ROTATED | REVOKED | EXPIRED

ChatChannel: ACTIVE -> ARCHIVED
```

Invalid/repeated transitions return a stable conflict or the prior idempotent result; they do
not silently coerce state.

## Critical Transactions and Locks

1. **Create tenant**: account idempotency claim → Tenant → owner membership → tenant roles →
   owner binding → general channel → audit → idempotency completion.
2. **Accept invitation**: lock invitation → validate expiry/revocation/capacity → upsert-safe
   membership → role binding → acceptance → increment use count → audit → idempotency completion.
3. **Owner changes**: lock active owner bindings/memberships → apply change only if another
   active owner remains → audit.
4. **Publish form**: lock template/latest version → validate/compile schema → allocate next
   version → publish and update template pointer → audit.
5. **Complete media**: lock media row → HEAD/check object through adapter → compare signed
   constraints/checksum → READY or REJECTED → audit/idempotency completion.

## Migration Notes

- Initial Prisma migration creates enums/tables/composite keys and standard indexes.
- A reviewed SQL section adds CHECK constraints Prisma cannot express fully, including
  effective date order, branch-scope branch presence, positive invitation limits, and media size.
- Seed uses stable UUID/name keys or deterministic upserts; it is safe to execute repeatedly.
- RLS is intentionally deferred, not assumed. If introduced, it requires a separate migration,
  connection-context design and negative tests without removing current authorization checks.
